Lesson 015 · Modul 15 · Publish Aplikasi — adaptasi: GitHub Releases

Anemia Care v1.0.0 sudah bisa di-download siapa aja 📦

Materi asli dosen: Modul 15: Publish ke Google Play Store.

Keputusan tercatat: berdasarkan arahan user, rilis dilakukan lewat GitHub Releases — ini persis Skenario C yang dosen sediakan sendiri buat yang belum punya akun Play Console (“Direct APK — share file .apk, user install manual”). Materi Play Store lengkap tetap dipelajari & dirangkum — AAB 49.4MB + keystore + signing dari M14 udah siap kalau mau lanjut ke Play Console ($25) kapan pun.

Inti materi dosen (Play Store) — dirangkum

  • Akun: Google Play Developer $25 sekali (personal: cocok mahasiswa; wajib verifikasi identitas KTP). Kebijakan 2023+: akun baru wajib closed testing 12 tester selama 14 hari sebelum produksi.
  • Create app: nama, bahasa (id-ID), App, Free, 2 deklarasi kepatuhan.
  • Asset wajib: app icon 512×512 (tanpa alpha), feature graphic 1024×500, minimal 2 screenshot per kategori device, promo video opsional. Tools gratis: Figma, Canva, appmockup, flutter screenshot.
  • Store listing: short description (≤80 char), full description (≤4000), icon, feature graphic, screenshot. Pola listing di materi: hook → ✨ fitur → 🔒 privasi → 💡 cocok untuk → footer.
  • App content: privacy policy (wajib — bisa gratis via GitHub Pages generator), ads, app access, content rating ESRB, target audience, data safety (app kita: “No data collected” — semua lokal!).
  • Closed testing → Promote: upload AAB → release notes format <id-ID>...</id-ID> → 12 tester → 14 hari → promote ke production → staged rollout (10% → 50% → 100%).
  • Update: naikkan versionCode/versionName di pubspec (1.0.0+1 → 1.1.0+2) → AAB baru → upload → release notes.
  • Penyebab ditolak: privacy policy mati, permission tak terpakai (ingat pelajaran kita: CAMERA gak dipasang — image_picker pakai intent sistem!), screenshot misleading, crash di device bersih, claim “resmi” tanpa lisensi, data safety inaccurate.

Adaptasi: Skenario C — GitHub Releases (yang dikerjakan)

Dosen juga menyediakan jalur tanpa Play Store, plus aturan “Wajib (semua skenario): buat halaman GitHub README berisi screenshot, deskripsi, dan link download”. Itu yang kita eksekusi:

  1. README.md — deskripsi, tabel fitur per modul, link download, cara build, teknologi, struktur, disclaimer medis.
  2. git init + commit — 219 file; rahasia signing (key.properties, upload-keystore.jks) dipastikan ke-ignore dulu sebelum commit.
  3. Repo public xzael24/anemia-care + push main.
  4. Release v1.0.0 dengan aset installable: 
    $ gh release create v1.0.0 \
    build/app/outputs/flutter-apk/app-release.apk \
    build/app/outputs/flutter-apk/app-arm64-v8a-release.apk \
    build/app/outputs/bundle/release/app-release.aab \
    --title "Anemia Care v1.0.0" --notes-file release-notes.md

Hasil: github.com/xzael24/anemia-care/releases/tag/v1.0.0 — APK universal 50.4MB, APK arm64 17.8MB, AAB 49.4MB, lengkap dengan release notes id-ID.

Jebakan nyata yang ketemu (dokumentasi penting!)

  • Env GITHUB_TOKEN invalid nge-block gh CLI — gh auth status nunjukin dua akun: token env (invalid, “active”) dan keyring xzael24 (valid). Semua perintah gh error 401 sampai env dibersihin (Remove-Item Env:GITHUB_TOKEN). Pelajaran: kalau gh aneh, cek dulu env var token vs keyring.
  • CRLF warnings saat commit — LF↔CRLF conversion warning normal di Windows; aman.
  • Quoting PowerShell di gh api -q — string query pakai kutip tunggal bikin parsing aneh; pakai file/heredoc atau >= 2 arg kena. (Minor.)

Tugas praktik

  1. Buka halaman Release → download app-arm64-v8a-release.apk (17.8MB) → install di HP → kasi screenshot ke repo (update README) kalau udah kebukti jalan.
  2. Bandingin: apa bedanya publish lewat GitHub vs Play Store? (jawaban: Play Store = discoverability + auto-update + review, tapi $25 + 12 tester 14 hari; GitHub = gratis & langsung, tapi install manual.)
  3. Kalau suatu hari mau Play Store: tinggal follow rangkuman materi — AAB + signing udah siap, cukup isi listing + content rating + privacy policy.

Q1: Rilis kita pakai skenario dosen yang mana?

Dosen nyediain Skenario C buat yang belum siap bayar $25 — kita pakai itu (GitHub Releases) + README wajib.

Q2: Yang WAJIB buat semua skenario menurut dosen…

README jadi halaman “wajib” lintas skenario — kita buat + link release langsung di dalamnya.

Q3: Keystore & key.properties ikut ke-commit ke GitHub?

Kita verifikasi via git check-ignore sebelum commit — keystore hilang = nggak bisa update app.

Q4: GITHUB_TOKEN env invalid bikin gh CLI…

Env var override keyring — solusi: Remove-Item Env:GITHUB_TOKEN lalu gh normal lagi.

Q5: Kalau mau lanjut ke Play Store, yang udah siap dari M14…

Play Console tinggal isi listing + asset + content rating — fondasi AAB & signing udah beres.
