Lesson 014 · Modul 14 · Build Aplikasi untuk Release — APK & AAB

Anemia Care sekarang punya identitas rilis: nama, ikon, splash & tanda tangan 🔏

Materi asli dosen: Modul 14: Build APK & AAB.

Cara dosen: pakai project lama (flutter_widget_dasar) yang udah matang. Kita: pakai project anemia sendiri (per keputusan awal: satu project berkembang). Yang dikerjakan: nama aplikasi, Application ID, ikon + adaptive icon, splash screen native, keystore upload + signing config, lalu (percobaan) build APK.

APK vs AAB

1. Nama aplikasi

android/app/src/main/AndroidManifest.xml → android:label="Anemia Care" (sebelumnya "anemia" — huruf kecil semua, kurang proper buat home screen).

2. Application ID (yang NGGK bisa diubah lagi!)

// android/app/build.gradle.kts
defaultConfig {
    applicationId = "id.anemiacare.app"   // ganti com.example (tanpa reverse-domain)!
    versionCode = flutter.versionCode      // dari pubspec: 1
    versionName = flutter.versionName      // dari pubspec: 1.0.0
}

Format reverse-domain (com.perusahaan.app). ID ini tidak bisa diubah setelah pertama kali di-publish — jadi id.anemiacare.app masih placeholder: sebelum upload ke Play Store, ganti ke domain yang beneran lo punya. Catatan: namespace sengaja tetap com.example.anemia (internal, nggak berpengaruh ke Play Store) — menghindari pindah-pindah file MainActivity yang nggak perlu.

3. Ikon & adaptive icon — digenerate, bukan didesign 🎨

Tantangan: nggak ada designer & nggak ada asset ikon. Solusi jujur: ikon digenerate programmatically lewat tool/gen_icon.dart — script Dart murni yang menggambar droplet merah (darah = identitas anemia) di background gradient pink muda, dengan PNG encoder sendiri (zlib dari dart:io + CRC32 manual) + supersampling 2×2 buat anti-aliasing. Nggak pakai dependency image processing sama sekali.

$ dart run tool/gen_icon.dart
# → assets/icon/icon.png (1024, launcher) & assets/icon/splash_logo.png (512, transparan)

Lalu tool resmi Flutter:

$ dart run flutter_launcher_icons    # generate mipmap + adaptive icon dari icon.png
$ dart run flutter_native_splash:create  # splash native (termasuk Android 12/v31)

Bug nyata yang ketemu: CRC PNG ditulis sebelum data → ikon akhirnya nggak bisa di-decode. Fix urutan chunk. Pelajaran: kalau bikin binary format sendiri, selalu verifikasi dengan decoder sungguhan (di sini: package:image lewat flutter_launcher_icons).

4. Keystore & signing config

// Generate keystore upload (RSA 2048, valid 10000 hari = 27 tahun)
$ keytool -genkeypair -v -keystore android/app/upload-keystore.jks \
    -alias upload -keyalg RSA -keysize 2048 -validity 10000 \
    -storepass XXXXX -keypass XXXXX -dname "CN=Anemia Care, ..."
  • android/key.properties — kredensial (storePassword, keyPassword, keyAlias, storeFile). JANGAN di-commit → masuk .gitignore (sama kayak *.jks).
  • build.gradle.kts — load key.properties → signingConfigs.create("release") → release pakai keystore upload. Fallback ke debug key kalau key.properties belum ada (proyek baru/klonan nggak error).
buildTypes {
    release {
        signingConfig = if (keystorePropertiesFile.exists()) {
            signingConfigs.getByName("release")
        } else signingConfigs.getByName("debug")
    }
}

5. Versioning

Version udah benar dari template: version: 1.0.0+1 (versionName 1.0.0, versionCode 1) di pubspec.yaml → diteruskan ke gradle otomatis.

6. Build — hasil nyata (sukses semua!) 🎯

Ternyata RAM cukup (IDE/browser ditutup + setting memori gradle M11): gradle jalan mulus di background. Ini yang berhasil:

PerintahOutputUkuranWaktu
flutter build apk --debugapp-debug.apk150.72 MB206s
flutter build apk --releaseapp-release.apk50.4 MB476s
flutter build appbundle --releaseapp-release.aab49.4 MB109s
flutter build apk --release --split-per-abiapp-abi-release.apkarm64 17.8MB · v7a 15.3MB · x86_64 19.2MB184s

Kontras ukuran menarik: universal release 50.4MB vs split arm64 17.8MB (≈65% lebih kecil) — dalangnya: split cuma bawa 1 arsitektur CPU. Inilah yang Play Store lakukan otomatis dari AAB buat tiap device.

Detail menarik: font tree-shaken di release — MaterialIcons 1,645,184 → 5,752 byte (99.7% berkurang).

Verifikasi jujur dari dalam file:

$ aapt dump badging app-release.apk
package: name='id.anemiacare.app' versionCode='1' versionName='1.0.0'
application-label:'Anemia Care'

$ apksigner verify --print-certs app-release.apk
Signer #1 certificate DN: CN=Anemia Care, OU=Mobile Programming, O=Student, ...
    → ditandatangani keystore UPLOAD kita, bukan debug key ✅

Catatan build & best practices

  • Debug APK itu gemuk (150MB): semua ABI + debug runtime. Release jauh lebih kecil — bedanya signifikan.
  • Build berturut-turut makin cepat (cache gradle/kotlin). AAB 109s vs APK release 476s.
  • Bonus dosen --obfuscate --split-debug-info: minify R8 udah aktif otomatis di release Flutter; obfuscate optional — dipelajari sebagai teori (butuh keep rule untuk reflection; app kita nggak ada reflection).

Tugas praktik

  1. Cek hasil build di folder build/app/outputs/.
  2. Buka Play Console mindset: applicationId harus diganti ke domain lo sebelum publish (M15).
  3. Main flutter analyze & flutter test --concurrency=1 (35 test hijau).
  4. Kalau kepo: buka tool/gen_icon.dart — ganti warna/posisi droplet, jalanin ulang, regenerate ikon.
Catatan jujur: keystore & password tersimpan lokal (key.properties) — kalau file itu hilang, app nggak bisa di-update lagi di Play Store. Backup ke tempat aman (bukan repo!). Ini bukan hal yang bisa di-skip: tanpa tanda tangan, APK release nggak ada gunanya.

Q1: Format distribusi yang WAJIB untuk Play Store…

Play Store mewajibkan AAB sejak Agustus 2021 — Play yang ngebikin APK ramping per device.

Q2: Application ID boleh diubah kapan aja?

Itu sebabnya pakai reverse-domain beneran, bukan com.example (yang jadi placeholder di project kita).

Q3: Keystore upload & key.properties sebaiknya…

Keystore hilang = nggak bisa update app di Play Store selamanya. Gitignore udah dilindungin.

Q4: Ikon app digenerate dari…

Tanpa designer & tool desain: droplet merah digambar matematis + encoding PNG manual (zlib + CRC32).

Q5: Signing config release di build.gradle pakai…

Release APK wajib tanda tangan non-debug; fallback bikin proyek klonanan tetap bisa build tanpa error.
