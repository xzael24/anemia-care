Lesson 008 · Modul 8 · Navigation & Routing

Dashboard anemia sekarang multi-halaman

Materi asli dosen: Modul 8: Navigation & Routing.

App beneran butuh lebih dari satu halaman. Modul ini ngajarin cara pindah-pindah halaman — dan buat missi kita, tantangan dosen (Katalog Produk) kita ubah jadi Katalog Pasien: klik pasien di daftar → halaman detail → pilih "Catat ke Jadwal" → balik ke dashboard dengan data. Kebetulan pas banget buat app pemantauan anemia. 🩸

Konsep: Stack Navigation 🥞

Halaman di-flutter dikelola seperti tumpukan. Buka halaman baru = push ke atas tumpukan. Tombol back = pop dari atas:

[ DetailPasien ]  ← di push ke atas (terlihat)
[ Dashboard    ]
[ HomeShell    ]  ← paling bawah (pertama kali dibuka)

1. Navigator.push & pop — paling dasar

// Pindah halaman
Navigator.push(context,
  MaterialPageRoute(builder: (_) => const HalamanKedua()),
);

// Balik (atau biarin tombol back device yang handle)
Navigator.pop(context);

2. Passing data → halaman baru

Kirim lewat parameter constructor halaman tujuan:

class DetailPasienPage extends StatelessWidget {
  final String nama;
  final int umur;
  final double hb;

  const DetailPasienPage({super.key, required this.nama, required this.umur, required this.hb});
  ...
}
Navigator.push(context,
  MaterialPageRoute(builder: (_) => DetailPasienPage(
    nama: 'Silvi Rahmawati', umur: 22, hb: 10.2,
  )),
);

3. Return data — halaman baru balikin hasil

Navigator.push mengembalikan Future yang resolve saat halaman di-pop dengan data. Ingat async/await (Modul 5)? Ini dia dipakainya:

// Halaman pemanggil — tunggu hasilnya
final hasil = await Navigator.push<String>(
  context,
  MaterialPageRoute(builder: (_) => const DetailPasienPage(...)),
);

if (hasil != null && context.mounted) {
  ScaffoldMessenger.of(context).showSnackBar(
    SnackBar(content: Text('$hasil ditambahkan ke jadwal')),
  );
}

// Halaman tujuan — balikin data lewat pop
onPressed: () => Navigator.pop(context, nama),

context.mounted penting: ngecek widget masih nempel di tree sebelum pakai context setelah await (biar aman dari "use_build_context_synchronously").

4. Named routes — biar rapi kalau halamannya banyak

MaterialApp(
  initialRoute: '/',
  routes: {
    '/': (_) => const HomeShell(),
    '/tentang': (_) => const TentangPage(),
  },
)

Navigator.pushNamed(context, '/tentang');       // pindah
Navigator.pushReplacementNamed(context, '/home'); // replace (login → home)
Navigator.popUntil(context, ModalRoute.withName('/')); // pop sampe route tertentu

Tugas praktik (10 menit)

  1. flutter run → klik Silvi Rahmawati di daftar → halaman detail kebuka → tekan Catat ke Jadwal → balik ke dashboard + SnackBar muncul. Itu flow lengkap push/pop + passing/return data.
  2. Geser dari pinggir kiri / tap ikon ☰ → Drawer kebuka → Tentang Aplikasi → halaman Tentang (named route).
  3. Pindah tab bawah: Beranda ↔ Jadwal ↔ Info — perhatiin tab aktif & kontennya.
  4. Tantangan dosen (versi anemia): tambah tombol "Hapus dari Daftar" di DetailPasienPage yang pop(context, 'hapus:...'), dan di dashboard tampilkan SnackBar beda kalau prefix-nya hapus.

Kuis singkat

Q1: Buka halaman baru = … ke stack

push menumpuk halaman baru. pop membuang halaman teratas. Halaman dikelola seperti tumpukan.

Q2: Ngirim data ke halaman baru lewat…

Halaman tujuan terima data sebagai required parameters constructor — cara paling simpel & jelas.

Q3: Halaman tujuan balikin data ke halaman sebelumnya lewat…

pop(context, data) — argumen kedua pop adalah hasil yang di-await pemanggil.

Q4: Daftar rute terpusat di…

Named routes didaftarkan di MaterialApp.routes lalu dipanggil dengan pushNamed.

Q5: Setelah await, sebelum pakai context harus…

context.mounted memastikan widget masih ada di tree setelah await — mencegah error pakai context yang sudah mati.
