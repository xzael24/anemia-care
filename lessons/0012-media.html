Materi asli dosen: Modul 12: Pengelolaan Media (Image, Audio, File).

Sejak awal app ini punya menu cepat "Input Lab" yang cuma nampilin SnackBar "menyusul di modul berikutnya" 😅. Nah, modul ini penutupnya: mini-project dosen (Galeri Foto Pribadi) gue adaptasi jadi "Galeri Hasil Lab" — simpen foto hasil cek lab / bukti periksa, ambil dari kamera atau galeri, disimpan permanen di direktori dokumen perangkat, bisa dihapus (dengan konfirmasi), dan tiap foto otomatis dikasih label tanggal.

Permission

<!-- AndroidManifest.xml: dibaca dari dosen + deviasi dicatat -->
<uses-permission android:name="android.permission.INTERNET" />              <!-- M10 -->
<uses-permission android:name="android.permission.READ_MEDIA_IMAGES" />     <!-- M12, Android 13+ granular -->

Dosen minta daftar CAMERA + READ_EXTERNAL_STORAGE + READ_MEDIA_* lengkap. Deviasi tercatat: image_picker di Android jalan lewat intent sistem (Activity kamera / photo picker) — jadi permission CAMERA & storage nggak wajib; kalau dipasang tapi nggak dipakai, malah lint warning di release build. Yang masuk cuma READ_MEDIA_IMAGES (galeri). iOS butuh NSCameraUsageDescription + NSPhotoLibraryUsageDescription di Info.plist (dari dosen, di bagian teori).

Ambil foto + simpan permanen

final picked = await _picker.pickImage(
  source: ImageSource.camera,   // atau .gallery
  imageQuality: 80,             // kompres 80% — hemat storage
  maxWidth: 1280,
);
if (picked == null) return;     // user batal

final dir = await getApplicationDocumentsDirectory();
final nama = 'foto_${DateTime.now().millisecondsSinceEpoch}.jpg';
await File(picked.path).copy(join(dir.path, nama)); // salin dari cache → dokumen

pickImage ngasih file di cache sementara — kalau nggak dicopy, bisa ilang/kena bersihin sistem. Beda direktori: getTemporaryDirectory (boleh ilang) vs getApplicationDocumentsDirectory (persisten, ini yang kita pakai).

Service testable (pola yang sama kayak M10/M11)

class GaleriLabService {
  GaleriLabService({Future<Directory> Function()? getDir})
      : _getDir = getDir ?? getApplicationDocumentsDirectory;
  //       ^ produksi: direktori asli;  test: folder temp — plugin nggak perlu
}

Satu pattern yang kita terapkan terus sejak M10: dependency injection. getApplicationDocumentsDirectory butuh plugin native yang nggak ada di widget test, jadi biar test jalan offline, service nerima fungsi penyedia direktori yang bisa diganti.

Pelajaran terbesar modul ini: IO asli ≠ mock di widget test

Test file, gambar, dan delete itu IO nyata — beda kelas dari test M10 (MockClient = microtask doang). Widget test jalan di zona FakeAsync: file yang kebuka/ke-delete nggak akan pernah "rampung" tanpa bantuan. Tiga trik yang dipakai:

  1. Seeding sync — writeAsBytesSync/createTempSync biar zone-proof (sync jalan di mana aja).
  2. tester.runAsync() — buat kasih real time ke pipeline IO. Penting: satu runAsync cuma memajukan satu "hop" (delete kelar di OS → kontinuasinya antri microtask FakeAsync → cuma jalan pas pump → hop berikutnya mulai). Jadi harus alternasi pump ↔ runAsync berulang — helper settleDenganIO().
  3. errorBuilder di Image.file — foto korup/decode error jadi placeholder, bukan exception nyembur ke console. Di Windows, file yang megang handle gambar juga ketauan asiknya: delete() kena PathAccessException errno 32 kalau read gambar belum kelar.

Tugas praktik (10 menit)

  1. flutter run → Beranda → tap tile Input Lab → Galeri Hasil Lab kebuka (nggak ada lagi "menyusul" ✨).
  2. Tap ikon kamera 📷 di emulator → ambil foto (atau pilih dari galeri). Foto masuk grid dengan label tanggal.
  3. Tutup app & buka lagi → foto masih ada (tersimpan permanen di direktori dokumen).
  4. Long-press satu foto → coba "Batal", terus ulangi → "Hapus" → foto hilang + SnackBar hijau.
  5. Tap foto → preview besar. (Bonus: coba hapus pas galeri lagi ke-load — error state merah harusnya muncul kalau gagal.)
Catatan jujur: foto lo nyimpen di dalam folder internal app (nggak nyampur sama galeri HP) — itu keputusan yang benar buat data medis: app bisa dapet izin baca, tapi hasilnya nggak gampang bocor ke aplikasi lain.

Kuis singkat

Q1: Hasil pickImage() ditaruh di cache sementara. Biar nggak ilang, harus…

Picker kasih file di cache yang bisa dibersihin sistem; copy ke direktori dokumen biar persisten.

Q2: Kenapa GaleriLabService nerima getDir yang bisa di-inject?

Sama kayak JadwalStore di M11: produksi pakai path asli, test inject folder temp — logika teruji offline.

Q3: Widget test galeri butuh runAsync BERULANG karena…

IO asli (delete/file stream) cuma maju di real time (runAsync); kontinuasinya di microtask FakeAsync yang jalan pas pump — jadi harus bergantian.

Q4: Permission CAMERA nggak dipasang karena…

Intent Activity kamera jalan tanpa izin CAMERA di manifest; pasang tapi tak terpakai = "UnusedPermission" di release build.

Q5: Tantangan dosen yang di-lewatin dengan alasan jujur?

Audio nggak nyambung ke konteks app; fitur 1 & 2 malah masuk (bikin galeri makin usable).
