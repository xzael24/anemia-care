Lesson 009 · Modul 9 · State Management

Jadwal pemantauan beneran nyimpen data sekarang

Materi asli dosen: Modul 9: State Management.

State = data yang bisa berubah seiring waktu. Sampai Modul 8, data kita nempel mati di dalam widget — "Catat ke Jadwal" cuma ngasih SnackBar terus ilang. Modul ini benerin itu: todo-list dosen kita ubah jadi Jadwal Pemantauan, dan tab Jadwal sekarang beneran nyimpen pasien yang lo catat, bisa dicentang selesai, dihapus, dan dilihat statistiknya. 🗓️

Stateless vs Stateful — inget lagi

StatelessWidgetStatefulWidget
Isitetap sepanjang umurpunya data internal yang bisa berubah
ContohText, Icon, kartu profilcounter, form, tab aktif
Ubah tampilantidak bisasetState(() { ... }) → rebuild

1. setState — cara paling fundamental

class _CounterState extends State<CounterPage> {
  int _angka = 0;

  void _tambah() {
    setState(() { _angka++; });  // ← sinyal "build ulang!"
  }
  ...
}

Tanpa setState, nilainya berubah di memori tapi tampilan nggak ikut — karena Flutter cuma rebuild kalau dikasih tahu.

2. Lifting state up — berbagi ke sibling

Dua widget bersaudara yang perlu state yang sama → pindahkan state ke parent, terus turunin via constructor:

Column(children: [
  Tampilan(angka: _counter),                        // terima state
  Tombol(onTambah: () => setState(() => _counter++)), // ubah state
])

Masalahnya pas app besar: state dipakai halaman ke-4 dan halaman ke-1 → "prop drilling" sakit. Solusinya Provider 👇

3. ValueNotifier — reactive tanpa package

final counter = ValueNotifier<int>(0);

ValueListenableBuilder<int>(
  valueListenable: counter,
  builder: (context, value, _) => Text('$value'),
)

onPressed: () => counter.value++,

4. Provider — state global yang scalable (standar industri)

Tiga komponen:

KomponenPeran
ChangeNotifierclass penyimpan state + panggil notifyListeners() tiap berubah
ChangeNotifierProviderinject model ke widget tree
context.watch / context.readbaca state (watch = ikut rebuild, read = tanpa subscribe)
// 1) Model
class JadwalModel extends ChangeNotifier {
  final List<JadwalItem> _items = [];
  List<JadwalItem> get items => List.unmodifiable(_items);
  int get jumlahBelumSelesai => _items.where((i) => !i.selesai).length;

  void tambah(String nama) { _items.add(JadwalItem(nama)); notifyListeners(); }
  void toggle(int i) { _items[i].selesai = !_items[i].selesai; notifyListeners(); }
}

// 2) Inject
ChangeNotifierProvider(
  create: (_) => JadwalModel(),
  child: const AnemiaApp(),
)

// 3a) Baca + rebuild otomatis (pakai di build)
final model = context.watch<JadwalModel>();

// 3b) Baca doang, tanpa rebuild (pakai di event handler)
context.read<JadwalModel>().tambah('Silvi');

context.watch vs context.read — bedanya wajib hafal

watch<T>()read<T>()
Subscribe?yatidak
Rebuild?ya, tiap state berubahtidak pernah
Dipakai dibuild()onPressed dll.

Catatan deviasi: dosen nyuruh tombol "Hapus Semua Selesai" di bottom bar — kita taruh di bawah daftar karena shell app kita sudah punya tab bar (NavigationBar di Modul 8). Alasan dicatat, bukan dilupakan.

Tugas praktik (10 menit)

  1. flutter run → Beranda → klik pasien → Catat ke Jadwal → pindah tab Jadwal → pasiennya ADA di list, counter "1 belum selesai" di AppBar.
  2. Centang pasiennya → garis coret muncul, counter jadi "0 belum selesai", tombol Hapus Semua Selesai muncul.
  3. Tekan ikon 📊 di AppBar Jadwal → Statistik (Total 1, Selesai 1, 0% ... menyesuaikan). Balik, hapus item → statistik ikut berubah. Itu state global: satu sumber data, semua halaman sinkron.
  4. Tantangan dosen: tambah method resetSemua() di JadwalModel + tombolnya di halaman manapun yang lo mau.

Kuis singkat

Q1: Ganti tampilan di StatefulWidget harus dibungkus…

setState() adalah sinyal eksplisit ke Flutter untuk build ulang. notifyListeners() punya ChangeNotifier.

Q2: Dua widget bersaudara berbagi state → pindahkan ke…

Lifting state up: state di parent, diturunkan via constructor. Bukan file global (bikin kode sulit dilacak).

Q3: ChangeNotifier memberi tahu listener dengan…

notifyListeners() di panggil setelah state berubah di dalam ChangeNotifier. setState cuma untuk StatefulWidget.

Q4: Baca state + auto-rebuild saat berubah = pakai…

watch subscribe → rebuild. read hanya baca sekali, cocok untuk onPressed.

Q5: Setelah pop dengan data (M8), disimpan ke state global pakai…

read di event handler + method model (tambah) — data masuk ke satu sumber yang dipakai semua halaman.
